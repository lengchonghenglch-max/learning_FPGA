# UART RX 学习记录

## 1. 功能理解

### 它是什么？

`rxuart` 是 UART 接收模块。

它的任务是把串口输入线 `i_uart_rx` 上的串行比特流，按照 UART 协议还原成并行字节，并在一个字节接收完成后给出输出脉冲 `o_wr`。

它不是简单“把引脚电平读进来”，而是要完成下面几件事：

1. 对异步输入进行同步处理
2. 检测起始位
3. 按波特率节拍在合适时刻采样各数据位
4. 组装成 8 位数据
5. 检查奇偶校验、停止位、BREAK 等异常情况

### 为什么要单独学这个模块？

从 `linetest` 进入 `rxuart` 学习，不是重复学习，而是在“拆系统学模块”。

原因是：

- `linetest` 只是调用了 UART 接收模块
- 它能说明“系统怎么用 RX 的输出”
- 但真正完成“串行位流 -> 并行字节”转换的核心逻辑，在 `rxuart` 里面

可以类比成：

```text
linetest 负责调用和连接
rxuart   负责真正实现接收功能
```

因此，如果只看 `linetest`，我们知道“字节来了以后系统怎么处理”；
而继续学 `rxuart`，我们才能知道“这个字节到底是怎么被正确接收出来的”。

### 怎么工作？

先看它的主流程：

```text
i_uart_rx
   |
   v
同步寄存器(q_uart/qq_uart/ck_uart)
   |
   v
起始位检测
   |
   v
按 baud_counter 定时到比特中心采样
   |
   v
data_reg 移位接收
   |
   +--> parity / frame / break 检查
   |
   v
o_data + o_wr
```

### 最小例子

假设 UART 配置是 8N1，串口线上输入一个字符 `A`。

那么 `rxuart` 需要完成：

1. 等待空闲线为高电平
2. 检测到起始位拉低
3. 在起始位中间确认这是有效起始位
4. 每隔 1 个 baud 到比特中心采样 8 个数据位
5. 检查停止位是否为高
6. 输出 `o_data` 和 `o_wr`

## 2. 核心状态机 / 逻辑分析

### 当前先抓最重要的一层

`rxuart` 的状态机虽然复杂，但第一层只要先抓住这几个大状态：

- `RXU_RESET_IDLE`
- `RXU_IDLE`
- `RXU_BIT_ZERO ~ RXU_BIT_SEVEN`
- `RXU_PARITY`
- `RXU_STOP`
- `RXU_SECOND_STOP`
- `RXU_BREAK`

可以先把它理解成：

```text
等待空闲 -> 识别起始位 -> 逐位接收 -> 校验/停止位检查 -> 输出字节 -> 回到空闲
```

## 3. 关键知识点总结

### 今日先记 1 个总纲

UART RX 的核心不是“看见低电平就开始读”，而是：

```text
先确认起始位有效，再按位中心定时采样
```

为什么不能在检测到 `i_uart_rx` 变低的那一刻，就直接把它当成 `bit0` 开始采样？

原因有两层：

1. 那一刻只是“边沿刚出现”，不是比特中心  
UART 接收最稳定的采样点通常在每个比特的中间，而不是刚发生跳变的边沿处。  
如果一看到低电平就立刻采样，采到的时刻太靠近边沿，最容易受抖动和时序偏差影响。

2. 这个低电平不一定是真正的起始位  
它也可能只是毛刺、噪声，或者异步输入带来的瞬时不稳定。  
所以 `rxuart` 会先等半个 baud，到起始位中间再确认一次：如果这时仍然是低电平，才认为这是有效起始位。

因此更准确地说：

```text
i_uart_rx 只是原始串口线电平
不能单靠“看到变低”就认定一个字节开始
必须先确认起始位，再开始按位中心采样
```

为什么 `rxuart` 里要先用 `q_uart`、`qq_uart`、`ck_uart` 把异步输入连续打一拍、两拍、三拍？

核心原因是：

```text
UART 输入相对于系统时钟是异步的
不能直接拿来驱动后级状态机
```

更准确地说，这样做主要是为了降低亚稳态向后级逻辑传播的风险。

- `i_uart_rx` 来自芯片外部，不和 `i_clk` 对齐
- 如果在时钟边沿附近刚好发生变化，首级触发器可能进入亚稳态
- 多打一到两级寄存器，可以给前一级更多恢复时间
- 到 `ck_uart` 这一级时，送给后级状态机和计数器的信号会更稳定

所以这里的重点不是“简单滤毛刺”，而是：

```text
把异步输入先同步到本地时钟域
再交给后续接收状态机使用
```
