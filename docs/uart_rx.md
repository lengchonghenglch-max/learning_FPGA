# UART RX 学习记录

## 1. 功能理解

### 它是什么

`rxuart` 是 UART 接收器（UART Receiver）。

它负责把串口输入线 `i_uart_rx` 上的串行位流，还原成并行字节，并在一个字节接收完成后输出：

1. `o_data`：接收到的字节
2. `o_wr`：该字节有效的 1 拍脉冲

### 为什么不能只看 `i_uart_rx`

`i_uart_rx` 只是外部串口线的电平。

它只能表示：

1. 现在是高电平还是低电平
2. 电平什么时候翻转

但它不能直接告诉你：

1. 起始位是否真的成立
2. 现在采到的是第几位数据
3. 这个字节是否已经完整接收

### 怎么工作

```text
i_uart_rx
   |
   v
q_uart -> qq_uart -> ck_uart   同步到本地时钟域
   |
   v
half_baud_time                确认起始位中点
   |
   v
baud_counter / zero_baud_counter
   |
   v
state 逐位推进
   |
   v
data_reg 组装字节
   |
   v
o_data / o_wr
```

### 最小例子

如果外部发来一个 `8'h55`：

1. 串口线先从高拉低，表示起始位开始。
2. `rxuart` 不会立刻把这个低电平当作数据位。
3. 它会先等半个 baud，到起始位中间再次确认仍是低电平。
4. 然后每隔一个 baud 在各数据位中心采样一次。
5. 停止位检查通过后，输出 `o_data=8'h55` 和 `o_wr=1`。

## 2. 核心状态机 / 逻辑分析

### 2.1 总体状态流

可以先把 `rxuart` 理解成下面这条主流程：

```text
RESET_IDLE
   ->
IDLE
   ->
确认有效起始位
   ->
BIT0 ~ BIT7
   ->
PARITY(可选)
   ->
STOP / SECOND_STOP
   ->
o_wr 拉高
   ->
回到 IDLE
```

### 2.2 为什么要等半个 baud

因为起始位刚出现的边沿最不稳定。

如果一检测到低电平就立即采样，会有两个风险：

1. 采样点太靠近边沿，容易受抖动影响。
2. 这个低电平可能只是毛刺，不是真正起始位。

所以必须等到“起始位中心”再确认一次。

### 2.3 为什么要用 `q_uart/qq_uart/ck_uart`

这是异步输入同步链。

原因是 UART 输入相对于系统时钟 `i_clk` 是异步的，不能直接送入后级状态机，否则容易把亚稳态传播到逻辑里。

这 3 级寄存器的作用是：

1. 先把异步输入打一拍。
2. 再继续同步，降低亚稳态影响。
3. 最终给状态机一个更稳定的 `ck_uart`。

### 2.4 为什么要靠 `zero_baud_counter` 推进状态

因为 UART 是“按位时间采样”的，不是“每个系统时钟采样一位”的。

只有在真正到达一个位的中心采样点时，状态机才应该前进一步。

否则会出现：

1. 同一个位被重复读很多次
2. 状态机推进过快
3. 数据位和停止位边界全部错位

## 3. 关键知识点总结

### 3.1 起始位检测 和 数据位采样 不是同一件事

起始位检测的作用是：

```text
确认“一个新字节开始了”
```

数据位采样的作用是：

```text
在正确的位中心，把 bit0~bit7 真正读出来
```

这两个动作必须拆开。

### 3.2 中心采样的价值

中心采样（Center Sampling）就是尽量在每个 bit 的中间位置采样。

它的意义是：

1. 离边沿最远
2. 最不容易被抖动影响
3. 对时钟偏差的容忍度更高

### 3.3 `o_wr` 不是“线回到高电平”就拉高

`o_wr` 只有在下面几件事都完成后才会拉高：

1. 所有数据位采完
2. 停止位检查结束
3. 字节已经装配完成

因此，`o_wr` 是“字节级完成信号”，不是“引脚电平变化信号”。

## 4. ModelSim 波形分析

### 4.1 本节要回答的核心问题

```text
rxuart 是如何证明自己在“位中心”采样，而不是乱采样的？
```

### 4.2 推荐观察信号

优先观察下面这些信号：

1. `i_uart_rx`
2. `dut.q_uart`
3. `dut.qq_uart`
4. `dut.ck_uart`
5. `dut.chg_counter`
6. `dut.half_baud_time`
7. `dut.state`
8. `dut.baud_counter`
9. `dut.zero_baud_counter`
10. `dut.data_reg`
11. `o_data`
12. `o_wr`

### 4.3 建议分 3 段看

#### 阶段 1：毛刺 / 短低电平

先制造一个短于半个 baud 的低脉冲。

你要确认：

1. `i_uart_rx` 的确出现了低电平。
2. 但是 `half_baud_time` 不成立。
3. 状态机不会进入真正的数据接收流程。

这一步是为了说明：

```text
不是看到低电平就算起始位
```

#### 阶段 2：有效起始位

发送一个完整字节时，你要确认：

1. 起始位拉低后，经过半个 baud，`half_baud_time` 变为有效。
2. `state` 从 `IDLE` 进入数据位接收状态。
3. 说明这个低电平被认定为“有效起始位”。

#### 阶段 3：逐位采样与输出

要确认：

1. `zero_baud_counter` 周期性有效。
2. 每次它有效时，`state` 才推进。
3. `data_reg` 只在这些关键采样点更新。
4. 停止位结束后，`o_data` 更新，`o_wr` 拉高 1 拍。

### 4.4 波形里应该写出的结论

工程日志建议写成这种句子：

```text
在短低脉冲阶段，i_uart_rx 虽然被拉低，但 half_baud_time 未形成有效起始位判定，
状态机没有离开 IDLE。发送完整字节后，rxuart 在起始位中点完成确认，
随后仅在 zero_baud_counter 有效时推进状态并更新 data_reg，
最终在停止位检查完成后输出 o_wr，证明接收采用中心采样机制。
```

## 5. Debug / 遇到的问题

### 问题 1

为什么 `i_uart_rx` 不能直接代表“输入开始”？

因为它只是原始线电平，不是协议层事件。  
协议层“开始接收一个字节”的判定，必须由同步、半个 baud 确认、状态机转移共同完成。

### 问题 2

为什么需要 3 级同步寄存器？

因为异步输入可能在时钟边沿附近变化，导致首级寄存器进入亚稳态。  
多级同步的目标是把这个风险尽量隔离在前级，不让后面的状态机直接使用不稳定信号。

## 6. 解决方案和验证结果

### 解决方案

1. 用 testbench 先注入一个短毛刺。
2. 再发送两个完整字节。
3. 在波形中观察起始位确认、位中心采样、最终 `o_wr` 输出。

### 预期验证结果

1. 毛刺不会被当作有效起始位。
2. 真正字节只在位中心被采样。
3. `o_wr` 只在字节完整结束后输出 1 拍。
